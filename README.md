## Git 가이드

### 브랜치 구조

- `main` — 배포용 (직접 커밋 X, PR로만 병합)
- `develop` — 개발 통합 브랜치 (간단한 문서/설정 수정은 직접 커밋 가능)
- `feat/○○`, `fix/○○` 등 — 작업용 브랜치 (develop에서 분기 → PR로 병합 후 develop으로)

### 브랜치 네이밍

```
<타입>/<간단한-설명>
```

| 타입      | 용도         | 예시                 |
| --------- | ------------ | -------------------- |
| `feat/`   | 새 기능 개발 | `feat/login-api`     |
| `fix/`    | 버그 수정    | `fix/token-expiry`   |
| `docs/`   | 문서 작업    | `docs/api-spec`      |
| `chore/`  | 설정/기타    | `chore/ci-setup`     |

- 소문자 + 하이픈(`-`)으로 단어 구분
- 병합 완료된 브랜치는 삭제

### 커밋 메시지

```
<타입>: <간결한 설명>
- <상세내용 (선택)>
```

| 타입       | 용도                                      |
| ---------- | ----------------------------------------- |
| `feat`     | 새로운 기능 추가                          |
| `fix`      | 버그 수정                                 |
| `docs`     | 문서 변경                                 |
| `style`    | 코드 포맷팅 등 (로직 변경 없음)           |
| `refactor` | 리팩토링 (기능 변경 없음)                 |
| `test`     | 테스트 추가/수정                          |
| `chore`    | 빌드, 설정, 패키지 등 기타 작업           |

**예시**

```
feat: 로그인 API 구현

feat: FastAPI 프로젝트 초기 세팅
- 프로젝트 폴더 구조 생성 (routers, services, models)
- main.py 작성 (FastAPI 앱 + CORS 설정)

fix: 토큰 만료 시 500 에러 수정

docs: Git 가이드 추가 (README)
```
